# WindowRanger 1.0.10

WindowRanger 1.0.10 keeps windows tiled when an application refuses to shrink below its minimum size.

## Fixed

- Reversing keyboard resize now lets a neighbouring tile move inward before growing when an application ignores the initial size write at the screen edge. The retry checks the actual frame and preserves dialog protections.
- A refused resize no longer makes a normally managed window float. Tiled layouts account for the size the window accepts and give neighbouring windows the remaining space.
- Left-edge resizing with mismatched pointer and window observations no longer starts a move when the other edges remain stationary.
- Unsettled resize requests receive bounded retries. If a layout cannot fit every window, WindowRanger preserves a valid previous layout or current window sizes instead of removing a participant.

## Diagnostics

- Focused-window reports include provisional size constraints, the last requested and observed sizes, and retry exhaustion. Background layout records retain requested and actual frames together.

## Requirements and installation

Requires macOS 14 or later and Accessibility permission. Screen Recording is needed only for optional captured workspace previews.

Download `WindowRanger-1.0.10.dmg` and drag WindowRanger onto the Applications shortcut. A notarized ZIP, checksums and provenance manifest are also included. Existing users can use **Check for Updates…** after the feed is published, or run `brew upgrade --cask appranger/tap/windowranger`.

## Known limitations

Application minimum sizes cannot be overridden. If the display cannot accommodate all windows at their accepted sizes, a non-overlapping layout may be impossible. Fixed-size dialogs retain their existing protections.

The reported edge-double-click recurrence passed maintainer testing in the signed local candidate. This does not establish that every intermittent resume-related window-management issue is resolved.
